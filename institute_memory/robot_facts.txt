AUBIE (SpotMicro Robot Dog) — Key Facts

Physical robot: a 12-servo SpotMicro quadruped, "Aubie," built by Matthew.
Two compute sides:
  - Zephyr/STM32U585 MCU: runs servos, TFT face, sonar (compiled sketch)
  - QRB2210 Linux side: runs aubie_dog.py (bridge API, port 8420) and
    aubie_listen.py (wake-word listener)
Reached via Tailscale at 100.66.110.65, SSH as user "arduino".
The heavy AI (speech-to-text, the LLM, face recognition, text-to-speech)
does NOT run on the robot itself — it runs on a separate always-on server
(the "Ryzen machine") and the robot talks to it over the network.

Hardware history worth knowing:
  - The robot has an IWDG (independent watchdog timer) added to self-recover
    from I2C-hang freezes on the Zephyr/STM32U585 side.
  - Fixed a firmware bug where the front-right hip would go limp during
    gait stepping; also fixed a PCA9685 (servo driver) dropout-latch issue.
  - An LD19 LiDAR is wired in and working (live radar view exists).
  - Two Modulino Distance (ToF) sensors are mounted on the robot's
    underbelly for ground-sensing while walking.
  - PAM8002A amp + speaker modules replaced the original EMEET speaker.
  - CONFIRMED BAD HARDWARE: an 8-in-1 USB hub used to power the board (and
    carry its camera+speaker/mic) delivered power unreliably and caused
    full-board hangs/hard reboots. Powering the board directly (not
    through that hub) fixed it immediately. Any similar build (e.g. for
    someone replicating this setup) should power the board's main compute
    directly, and only route low-power peripherals through a hub.

Operational notes:
  - Never manually run "arduino-app-cli app restart" on the robot — a
    cron job already does this every 5 minutes, and running it manually
    collides with the automatic one over a shared hardware line (SWD).
  - Concurrent Bridge.call() RPCs to the robot can wedge the shared link;
    the HTTP API is the safer way to talk to it.
